#+TITLE: Emacsen

Build an Emacs release, tag or branch, from upstream or a local clone, into a Docker image. Run it in isolation, or install it into the host's =/usr/local=. emacsen compiles nothing on the host.

* Requirements

- Linux; =run= and =exec= require kernel 5.12+ for recursive read-only bind mounts.
- Docker Engine 25+ with BuildKit, access to the daemon.
- Bash 5, Git, curl, GNU coreutils and findutils, util-linux =flock=.

* Quick start

#+begin_src sh
./emacsen build 31.1
./emacsen run 31.1 -- -Q
#+end_src

To install on an Ubuntu 26.04 host, see Install on the host.

* Choose what to build

A recipe, =recipes/NAME/recipe=, names a source and a builder; =NAME= is the target of every command but =uninstall=. The ubuntu-26.04 builder is verified with 31.1 and master; other versions are untested with it.

** Shipped recipes

| Recipe | Source              | Builder      | Host installation |
|--------+---------------------+--------------+-------------------|
| 26.3   | GNU release tarball | 26.3         | No                |
| 31.1   | GNU release tarball | ubuntu-26.04 | Ubuntu 26.04      |
| master | Locked Git commit   | ubuntu-26.04 | Ubuntu 26.04      |

** A release

Using 30.2 as an example, create =recipes/30.2/recipe=:

#+begin_example
source=tarball
url=https://ftp.gnu.org/gnu/emacs/emacs-30.2.tar.xz
sha256=SHA256
version=30.2
builder=ubuntu-26.04
#+end_example

=sha256= is the only check emacsen applies to the download; take it from a tarball whose GNU signature you have verified.

#+begin_src sh
./emacsen build 30.2
#+end_src

** A tag or branch

Create =recipes/emacs-30.2/recipe=; for a branch, set ~ref=refs/heads/BRANCH~:

#+begin_example
source=git
url=https://github.com/emacs-mirror/emacs.git
ref=refs/tags/emacs-30.2
builder=ubuntu-26.04
#+end_example

Lock the ref, then build:

#+begin_src sh
./emacsen update emacs-30.2
./emacsen build emacs-30.2
#+end_src

=update= resolves =ref= in the source repository and writes its commit to =recipes/NAME/lock=, which is not edited by hand; an annotated tag locks the commit it names. Builds use the lock unchanged, and refuse a Git recipe without one, a lock whose =ref= differs from the recipe's, and a lock naming anything but a commit.

** Follow a branch

Run =update= again to move the lock to the branch's current commit, then rebuild:

#+begin_src sh
./emacsen update master
./emacsen build master
#+end_src

** A commit or local branch

Recipes name a ref, never a commit. To build a commit, create a branch for it in a local clone; work already on a local branch needs none:

#+begin_src sh
git -C /absolute/path/to/emacs branch experiment COMMIT
#+end_src

Create =recipes/experiment/recipe=:

#+begin_example
source=git
url=/absolute/path/to/emacs
ref=refs/heads/experiment
builder=ubuntu-26.04
#+end_example

No push is required.

#+begin_src sh
./emacsen update experiment
./emacsen build experiment
#+end_src

Keep the locked commit in the clone; a rebuild with an empty source cache fetches it again.

* Build

#+begin_src sh
./emacsen build 31.1
#+end_src

Each build runs =docker build --pull --load= and tags the local image =emacsen:NAME=. A rebuild moves the tag; the previous image remains, untagged, until pruned. The Ubuntu 26.04 base floats and Ubuntu packages are unpinned, so rebuilds can differ; the 26.3 base is digest-pinned.

Variants, for builders that declare them:

- =x= :: Selected when =dpkg= reports =libx11-6= installed. X11, Xft, DBus, JPEG, PNG, RSVG, TIFF and XPM.
- =server= :: Selected otherwise, including on hosts /without/ =dpkg=. No X11, DBus, GConf, GSettings or sound.

=--variant x|server= overrides detection; refused for builders without variants.

* Run without installing

#+begin_src sh
./emacsen run 26.3 -- -Q --batch --eval '(princ emacs-version)'
./emacsen exec 26.3 -- sh -c 'printf "%s\n" "$PWD"; id'
#+end_src

=run= starts the image's Emacs with the arguments after =--=; =exec= starts a command from the image's =PATH=. Both mount the workspace, the current directory or =--directory DIR=, read-only at =/work= and start in it. Pass =-Q= for compatibility checks.

Each run is a fresh container:

- The workspace is read-only; write to =/tmp=.
- =HOME= starts empty and is discarded on exit: no init file, packages or host configuration carry over.
- No network: =package-install= fails, so keep dependencies in the workspace.
- When stdin and stdout are a terminal, the container gets one, and stdout and stderr share it; redirect to separate them.
- The exit status is Emacs's or =COMMAND='s. emacsen's own errors exit 1 with the stderr prefix =emacsen:=; Docker failures exit 125 to 127: 126 for a non-executable =COMMAND=, 127 for one not found.
- As root, or under rootless Docker, the workspace must be world-readable.

** Test a package

Run ERT from source, then from bytecode compiled by the image's Emacs: older Emacs cannot generally run newer bytecode. Load sources by absolute path; =-L /work= would prefer host-compiled =.elc= files. Keep newer Emacs source trees' =lisp/= off =load-path=, where they shadow the image's ERT and standard libraries.

The examples expect =my-package.el= and =test/my-package-tests.el= in =$package=, the workspace, with no dependencies. Add dependencies placed there to =load-path= in both passes.

#+begin_src sh
package=/path/to/my-package
./emacsen run 26.3 --directory "$package" -- -Q --batch \
  -l /work/my-package.el -l /work/test/my-package-tests.el \
  -f ert-run-tests-batch-and-exit
#+end_src

The workspace is read-only and each invocation is a new container, so one =exec= compiles copies in =/tmp=, then loads the bytecode in a second Emacs process. One process would hide code that works only because compilation evaluated it.

#+begin_src sh
./emacsen exec 26.3 --directory "$package" -- sh -c '
  cp -- my-package.el test/my-package-tests.el /tmp &&
  emacs -Q --batch -L /tmp -f batch-byte-compile /tmp/my-package.el /tmp/my-package-tests.el &&
  emacs -Q --batch -L /tmp -l /tmp/my-package-tests.elc -f ert-run-tests-batch-and-exit'
#+end_src

* Install on the host

=install NAME= runs Emacs's own =make install= from the image's retained build tree into the host's =/usr/local=. It requires a rootful Docker daemon and an image built for the host's OS release; =docker= group membership is root-equivalent.

** Host libraries

Host packages for an installed Emacs on Ubuntu 26.04, beyond the desktop or terminal libraries already present. Containers carry their own. Run as root:

=x=:

#+begin_src sh
apt install libgccjit0 liblcms2-2 libtree-sitter0.25
#+end_src

=server=:

#+begin_src sh
apt install libgccjit0 libgnutls30t64 libncurses6 libtree-sitter0.25 libxml2-16
#+end_src

Native compilation needs the =libgccjit= runtime matching the builder's GCC version. After a host release upgrade, target the new release in the builder and rebuild; changed library sonames can break installed binaries.

Tree-sitter 0.25 loads ABI 15 grammars. Emacs 31+ installs grammars on demand into =~/.emacs.d/tree-sitter= (=treesit-auto-install-grammar=, =M-x treesit-install-language-grammar=), which needs Git and a C compiler on the host.

** Install

#+begin_src sh
./emacsen install 31.1
#+end_src

To inspect the result first, install into a scratch directory. =--into= stages the files without relocating Emacs. They are owned by root, so removing them needs root.

#+begin_src sh
./emacsen install 31.1 --into "$HOME/emacs-preview"
#+end_src

Rebuilding before the real install invalidates the preview.

** What gets installed

Different Emacs versions coexist in version-named directories. Reinstalling the same version, including another recipe or variant, replaces that version's files and record. The last install owns the shared files: =bin/emacs= links to its =emacs-VERSION=; =emacsclient=, =etags=, =ebrowse=, the manuals and the man pages are replaced. emacsen does not prune.

Install copies the C sources to =share/emacs/VERSION/src=. =find-function= and the help buffers' C source links reach them without the build tree, under =-Q= too.

** Uninstall

=uninstall VERSION= runs Emacs's own =make uninstall= from the image recorded for the installed version =VERSION=, selected by ID: a moved tag does not affect it, and a missing image is an error. =VERSION= is the installed Emacs's version, as =emacs --version= reports it. Removal runs inside that image, so the host's OS release need not match. It requires exactly one recorded version, because =make uninstall= also removes the shared files, and does not detect files replaced outside emacsen. Keep that image until uninstall. Its ID is the =image-id:= line of the record =/usr/local/lib/emacsen/installed/VERSION=. A rebuild untags it and =docker image prune= deletes it; tag it to keep it:

#+begin_src sh
docker tag "$(sed -n 's/^image-id: //p' /usr/local/lib/emacsen/installed/31.1)" emacsen-installed:31.1
#+end_src

* Reference

** Recipe format

=recipes/NAME/recipe=, =NAME= being a letter or digit, optionally followed by letters, digits, =.=, =_= or =-=. One ~key=value~ per line, no spaces around ~=~; the value runs verbatim to the end of the line. Lines starting with =#= are comments. A repeated key, or one not listed for the recipe's source, is refused.

- =source= :: Required. =tarball= or =git=.
- =url= :: Required. Tarball: download URL. Git: repository URL, absolute path or =file://= URL.
- =sha256= :: Tarball only, required. Lowercase hex digest of the tarball.
- =ref= :: Git only, required. Full ref name, such as =refs/tags/emacs-30.2= or =refs/heads/master=.
- =builder= :: Required. A directory under =builders/=.
- =version= :: Optional. The expected =emacs-version=; the build fails on a mismatch.
